# Accessibility Evaluation Matrix (WCAG 2.2 AA & 8-Part Manual Protocol)

**Ticket & Requirement Traceability:** `T09`, `NFR-004`, `UI-001`..`UI-024`, `@S42`, `@S51`

This document defines the authoritative **8-part manual accessibility evaluation matrix** complementing automated `axe-core` and Playwright accessibility checks. Release readiness (`evaluate_dynamic_release_readiness` in `crates/application/src/lib.rs`) requires both automated verification and sign-off across all 8 manual evaluation parts before production launch (`@S42`).

---

## 8-Part Manual WCAG 2.2 AA Evaluation Matrix

| Part | Evaluation Dimension | WCAG 2.2 AA Criteria | Target Journeys & UI Surfaces | Verification Protocol | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Keyboard-Only Navigation & Focus Order** | Full operability without a pointer across all learner, publisher, curator, and moderator workflows. | `2.1.1 Keyboard`, `2.1.2 No Keyboard Trap`, `2.4.3 Focus Order`, `2.4.7 Focus Visible`, `2.4.11 Focus Not Obscured (Minimum)` | Goal Intake (`UI-001`), Curriculum DAG & Module Tree (`UI-003`), Assessment Runner (`UI-008`), Adaptation Diff Modal (`UI-007`), Public Template Discovery & Adoption (`UI-009`, `UI-017`) | Navigate end-to-end using `Tab`, `Shift+Tab`, arrow keys, `Enter`, `Space`, and `Escape`. Verify logical focus order, visible `:focus-visible` indicator ($\ge 2\text{px}$ outline with $\ge 3:1$ contrast), and clean focus restoration on dialog close. | Verified |
| **2. Screen Reader Announcements & Live Regions** | Semantic landmarks, accessible names/descriptions, and polite/assertive ARIA live region updates. | `1.3.1 Info and Relationships`, `4.1.2 Name, Role, Value`, `4.1.3 Status Messages` | Async Generation Status (`UI-018`), Assessment Assistance & Mastery Cap Banner (`UI-008`, `@S15`), Prerequisite Gate Alert (`@S14`), Credit Reservation & 4-Cost-Bucket Breakdown (`UI-013`, `@S30`) | Audit with VoiceOver (macOS/iOS) and NVDA (Windows). Verify `aria-live="polite"` announces generation stage transitions (`queued -> retrieving -> generating -> validating -> succeeded`) and `role="alert"` announces validation or billing errors without stealing focus. | Verified |
| **3. Color Contrast & Non-Color State Differentiation** | Text, interactive controls, proficiency badges, and four-bucket cost indicators never rely on color alone. | `1.4.1 Use of Color`, `1.4.3 Contrast (Minimum)`, `1.4.11 Non-text Contrast` | Objective Proficiency States (`unassessed`, `in_progress`, `demonstrated`, `needs_review`, `waived`), 4 Cost Buckets (`learning_material`, `certification_fee`, `hosted_service_charge`, `byok_provider_telemetry`), Moderation Banners (`UI-024`) | Verify $\ge 4.5:1$ contrast for body text and $\ge 3:1$ for large text and UI components. Confirm every proficiency badge and cost bucket pairs color with an explicit text label and distinct icon shape. | Verified |
| **4. Reflow, 200% Text Zoom & Responsive Viewport** | Lossless layout reflow at `320 CSS px` width and `200%`–`400%` browser zoom without horizontal scrolling of reading content. | `1.4.4 Resize Text`, `1.4.10 Reflow`, `1.4.12 Text Spacing` | Curriculum Revision Diff (`UI-007`), Sanitized Publication Preview (`UI-009`), Hosted Wallet & Ledger Table (`UI-013`, `UI-020`) | Test at `1280x800` zoomed to `400%` (`320 CSS px` effective width) and with custom text-spacing overrides (`line-height: 1.5`, `letter-spacing: 0.12em`). Verify no clipped controls or overlapping sticky headers. | Verified |
| **5. Reduced Motion & Cognitive Load Control** | Honoring `prefers-reduced-motion: reduce` and eliminating auto-advancing or flashing transitions. | `2.2.2 Pause, Stop, Hide`, `2.3.1 Three Flashes or Below Threshold`, `2.5.8 Target Size (Minimum)` | Generation Progress Skeleton (`UI-018`), Diagnostic Adaptive Transitions (`UI-005`), Spaced Review Queue (`UI-006`) | Enable `prefers-reduced-motion: reduce` at OS level; verify animations collapse to instant opacity dissolves and all interactive touch/pointer targets meet $\ge 24\times 24\text{ CSS px}$. | Verified |
| **6. Form Error Identification, Recovery & Redundant Entry** | Programmatic error association (`aria-invalid`, `aria-describedby`) and preservation of learner input across retries. | `3.3.1 Error Identification`, `3.3.2 Labels or Instructions`, `3.3.3 Error Suggestion`, `3.3.7 Redundant Entry` | Goal Clarification & Feasibility Recovery (`@S01`, `@S02`), BYOK Credential Registration (`UI-012`), Notification IANA Timezone & Quiet Hours (`UI-011`, `@S32`) | Trigger validation errors (infeasible timeline, invalid IANA timezone, expired usage quote); verify inline recovery suggestions and confirm user inputs remain populated across retries. | Verified |
| **7. Accessible Authentication & Session Expiry Recovery** | Passwordless/OTP authentication without cognitive puzzle barriers, supporting paste and password managers. | `3.3.8 Accessible Authentication (Minimum)`, `2.2.1 Timing Adjustable` | Sign-In / Verification Code Flow (`@S87`), Session Revocation & Re-authentication Banner | Verify `autocomplete="one-time-code"` and `autocomplete="email"`, unrestricted clipboard paste into the authentication code field, and graceful draft preservation if a session expires. | Verified |
| **8. Complex Pedagogical Widgets (DAG Explorer & Partial Adoption)** | Accessible tabular/tree equivalent for visual prerequisite graphs and transitive closure previews. | `1.1.1 Non-text Content`, `1.3.2 Meaningful Sequence`, `2.4.6 Headings and Labels` | Prerequisite Objective DAG (`@S10`), Partial Adoption Transitive Prerequisite Closure Selector (`@S58`, `@S61`, `UI-017`) | Verify that every visual DAG node/edge has a synchronized hierarchical list/tree view where auto-included prerequisite objectives are explicitly labeled (`"Auto-included prerequisite for <Objective>"`) and navigable via keyboard. | Verified |
