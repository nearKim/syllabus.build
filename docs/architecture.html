Syllabus.build System & Class Architecture

Engineering reference for the multi-language Syllabus.build monorepo: hexagonal Rust domain and persistence crates, contract-driven OpenAPI code generation, and zero-cycle TypeScript packages and web client collaborators.

  • Rust Workspace: 10 crates · Edition 2021 · Axum + PostgreSQL 16
  • TypeScript Workspace: 3 packages · 70 web modules · 0 circular dependencies
  • Contracts: specs/product.md · 71 OpenAPI operations · 18 open catalog entries

Monorepo Layered & Hexagonal Overview

specs/product.md drives all OpenAPI schemas, Rust contract descriptors, and TypeScript client/token artifacts. Runtime execution splits cleanly across the Node/Preact web application, the Axum HTTP API service, and the outbox lease worker, all converging on pure Rust domain invariants and transactional PostgreSQL 16 storage.

Rust Backend Class, Trait & Collaborator Diagram

Following the Google Rust Style Guide and collaborator decomposition, ApiAppState wires concrete adapters into stateless ApplicationService workflows. Persistence and LLM execution depend strictly inward on port traits (CatalogRetrievalPort, SyllabusRevisionPersistencePort, GenerationJobRepositoryPort, InferenceProvider, and AuthVerifier).

TypeScript Frontend & Packages Class, Interface & Collaborator Diagram

The former 5,330-line browserApp.ts god module is split into three single-responsibility collaborators (mountBrowserApp.ts, browserAppController.ts, and renderWebAppHtml.ts) plus navigationShell.ts, yielding strictly zero circular dependencies across all 70 modules while consuming typed contracts from @syllabus/api-client and @syllabus/ui.

Workspace Package & Crate Dependency DAG

Every dependency edge in Cargo.toml and pnpm-workspace.yaml flows strictly downward from delivery binaries and web entrypoints into pure leaf packages without cycles.

Syllabus Synthesis, 6-Gate Validation & Fail-Closed Promotion Pipeline

No LLM output is ever rendered directly or promoted without passing six deterministic domain and contract validators. Any failure drops onto the fail-closed rejection bus, archiving the rejected payload for audit, releasing reserved hosted credits, and leaving the learner's active syllabus revision untouched.
